# Sitzung: Ansprechpartner-Löschdialog und Veranstaltungsverwaltung

## Anforderungen

- [x] Im Löschdialog eines Ansprechpartners eine eindeutig sichtbare Schaltfläche **„OK, löschen“** ergänzen.
- [x] Veranstaltungen eines Jahres administrativ umbenennbar machen.
- [x] Veranstaltungen eines Jahres einzeln und passwortgeschützt vollständig löschbar machen.
- [x] Gesamte Anwendung auf Fehler, Datenintegrität und Laufstabilität prüfen.
- [x] Geprüften Stand als WebDev-Checkpoint sichern.

## Sicherheits- und Bedienkonzept

Das Umbenennen ist nur für Administratoren verfügbar. Das endgültige Löschen verlangt zusätzlich das Administratorpasswort, warnt ausdrücklich vor dem Datenverlust und ist für die letzte verbleibende Veranstaltung eines Jahres gesperrt. Die Löschung erfolgt in einer Datenbanktransaktion und entfernt die zur Veranstaltung gehörenden Planungsdaten einschließlich der zugehörigen Löschprotokolle in fremdschlüsselsicherer Reihenfolge.

## Bisherige Verifikation

Der reale Datenbank-Regressionstest bestätigte erfolgreich das Umbenennen, die Normalisierung von Leerzeichen, die Ablehnung doppelter Veranstaltungsnamen und die vollständige Löschung inklusive Ansprechpartner, automatisch angelegtem Helfer, Schicht, Bereichsansprechpartner, Helferzuweisung, Vor- und Nachbereitung, Material, Marketing, Genehmigung, Kuchen und Finanzen. Chromium-Tests bestätigten auf Desktop und Mobil die sichtbaren Löschbestätigungen und die Eventverwaltung. Ein im Mobiltest gefundener Kontrastfehler der Event-Löschbuttons wurde korrigiert und anschließend mit vier sichtbaren, jeweils 282 Pixel breiten Buttons erneut erfolgreich geprüft. Alle temporären Testveranstaltungen und Testkontakte wurden entfernt.

Die vollständige Qualitätssicherung war erfolgreich: TypeScript-Prüfung, 50 automatisierte Tests, Produktions-Build, Drizzle-Migrationsprüfung und `git diff --check`. Der bekannte Vite-Hinweis auf ein JavaScript-Bundle über 500 KB ist eine Optimierungsempfehlung und kein Laufzeitfehler. Die Datenbankprüfung ergab 0 Testveranstaltungen, 0 verwaiste Helferzuweisungen, 0 Jahr-/Event-Abweichungen und 0 veranstaltungsfremde Ansprechpartner-Zuordnungen.

Ein unabhängiges Review bemerkte zunächst, dass historische Löschprotokolle beim endgültigen Entfernen einer Veranstaltung personenbezogene Eventdaten behalten würden. Dieser Punkt wurde behoben: Eventbezogene Auditzeilen werden nun in derselben Transaktion vor dem Event gelöscht. Ein zusätzlicher Live-Test bestätigte sowohl diese Auditbereinigung als auch die serverseitige Sperre gegen das Löschen der letzten Veranstaltung eines Jahres. Die komplette Prüfstrecke wurde anschließend erneut erfolgreich ausgeführt.
